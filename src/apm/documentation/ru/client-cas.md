# Клиентские сертификаты

Клиентские CA для mutual TLS. Создайте профиль, загрузите PEM CA и при необходимости CRL, затем выберите его у SSL-хоста. Нужен настоящий CA; неверная подпись или истёкший CRL отклоняется. Доступно администратору.

## Настройки

### `name`

<!-- setting:name -->
Название ресурса для поиска и выбора в панели, например test. Не меняет его ID и связанные ресурсы.

Формат: `string`. По умолчанию: `обязательно`. Ограничения: minLength=1; maxLength=128.

Пример: `"test"`.

### `enabled`

<!-- setting:enabled -->
Включает объект в генерируемую конфигурацию. Выключенный объект сохраняется в панели. Изменение вступает в силу после сохранения и успешного применения.

Формат: `boolean`. По умолчанию: `true`.

Пример: `true`.

### `verify`

<!-- setting:verify -->
Для клиентского CA: on требует клиентский сертификат, optional проверяет его только при наличии. Это проверка клиента, а не сертификата сервера.

Формат: `string`. По умолчанию: `"on"`. Ограничения: on / optional.

Пример: `"on"`.

### `depth`

<!-- setting:depth -->
Максимальная глубина цепочки клиентского сертификата. Подберите под вашу PKI; слишком малая глубина отклонит корректные длинные цепочки.

Формат: `integer`. По умолчанию: `2`. Ограничения: minimum=1; maximum=10.

Пример: `2`.

### `fingerprint`

<!-- setting:fingerprint -->
Системный SHA-256 идентификатор версии PEM-файлов. Не редактируется; пути версионные, прежние ревизии сохраняются для отката.

Формат: `string / null`. По умолчанию: `null`.

Пример: `"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"`.

## Пример работы

Создайте ресурс с понятным названием, заполните обязательные поля и сохраните. Проверьте завершение apply в «Операциях». При ошибке angie -t исправьте параметры или зависимости; прежняя рабочая конфигурация сохраняется. Observer читает данные, admin удаляет ресурсы, которые больше не используются.
