# Группы backend

Группы серверов для балансировки маршрутов и потоков. Добавьте узлы, выберите стратегию и свяжите группу с маршрутом. Группа заменяет отдельный адрес и порт маршрута. Недоступные приложения не откатывают конфигурацию автоматически.

## Настройки

### `name`

<!-- setting:name -->
Название ресурса для поиска и выбора в панели, например test. Не меняет его ID и связанные ресурсы.

Формат: `string`. По умолчанию: `обязательно`. Ограничения: minLength=1; maxLength=128.

Пример: `"test"`.

### `enabled`

<!-- setting:enabled -->
Включает объект в генерируемую конфигурацию. Выключенный объект сохраняется в панели. Изменение вступает в силу после сохранения и успешного применения.

Формат: `boolean`. По умолчанию: `true`.

Пример: `true`.

### `peers`

<!-- setting:peers -->
Серверы группы: хотя бы один адрес и порт. Каждый сервер имеет вес, признак резерва и ручного отключения. Проверки доступности включают все не отключённые узлы.

Формат: `array`. По умолчанию: `обязательно`. Ограничения: minItems=1.

Пример: `[{"host": "127.0.0.1", "port": 8080}]`.

### `peers.host`

<!-- setting:peers.host -->
IP-адрес или имя приложения. В Docker используйте имя сервиса, доступное из сети Angie. Для приложения на macOS с Docker Desktop — host.docker.internal. Адрес 127.0.0.1 означает собственное окружение Angie.

Формат: `string`. По умолчанию: `обязательно`.

Пример: `"127.0.0.1"`.

### `peers.port`

<!-- setting:peers.port -->
Порт, на котором слушает приложение. Для Docker-сервиса в общей сети нужен внутренний порт контейнера, например 8080. Внешний порт прокси-хоста эта настройка не меняет.

Формат: `integer`. По умолчанию: `80`. Ограничения: minimum=1; maximum=65535.

Пример: `8080`.

### `peers.weight`

<!-- setting:peers.weight -->
Относительный вес сервера при балансировке. 2 получает примерно вдвое больше запросов, чем 1, если выбранная стратегия использует веса.

Формат: `integer`. По умолчанию: `1`. Ограничения: minimum=1; maximum=1000.

Пример: `1`.

### `peers.backup`

<!-- setting:peers.backup -->
Резервный сервер, используемый при недоступности основных. Не совместим со стратегией ip_hash. Мониторинг проверяет и резервные серверы.

Формат: `boolean`. По умолчанию: `false`.

Пример: `false`.

### `peers.down`

<!-- setting:peers.down -->
Ручное исключение узла из балансировки и проверок. Настройки сохраняются; включите узел обратно после восстановления.

Формат: `boolean`. По умолчанию: `false`.

Пример: `false`.

### `strategy`

<!-- setting:strategy -->
round_robin распределяет запросы по очереди, least_conn выбирает меньше соединений, ip_hash закрепляет IP клиента за сервером. Для stream ip_hash компилируется как consistent hash.

Формат: `string`. По умолчанию: `"round_robin"`. Ограничения: round_robin / least_conn / ip_hash.

Пример: `"round_robin"`.

## Пример работы

Создайте ресурс с понятным названием, заполните обязательные поля и сохраните. Проверьте завершение apply в «Операциях». При ошибке angie -t исправьте параметры или зависимости; прежняя рабочая конфигурация сохраняется. Observer читает данные, admin удаляет ресурсы, которые больше не используются.
