# Перенаправления

Перенаправления браузера на другой URL. Укажите домены, цель и код, при необходимости сертификат. Конфликт доменов с другим маршрутом отклоняется. Создание и изменение доступны администраторам и операторам.

## Настройки

### `name`

<!-- setting:name -->
Название ресурса для поиска и выбора в панели, например test. Не меняет его ID и связанные ресурсы.

Формат: `string`. По умолчанию: `обязательно`. Ограничения: minLength=1; maxLength=128.

Пример: `"test"`.

### `enabled`

<!-- setting:enabled -->
Включает объект в генерируемую конфигурацию. Выключенный объект сохраняется в панели. Изменение вступает в силу после сохранения и успешного применения.

Формат: `boolean`. По умолчанию: `true`.

Пример: `true`.

### `domains`

<!-- setting:domains -->
Доменные имена без протокола, порта и пути, по одному на строке. Например: app.example.com. DNS-записи настраиваются отдельно. Для сертификата на *.example.com нужна проверка DNS-01.

Формат: `array`. По умолчанию: `обязательно`. Ограничения: minItems=1.

Пример: `["app.example.com"]`.

### `target`

<!-- setting:target -->
Полный HTTP(S)-адрес назначения, например https://example.com. Это перенаправление браузера, а не проксирование запроса.

Формат: `string`. По умолчанию: `обязательно`.

Пример: `"https://example.com"`.

### `code`

<!-- setting:code -->
HTTP-код перенаправления: 301/308 постоянные, 302/307 временные; 307/308 сохраняют метод запроса.

Формат: `integer`. По умолчанию: `301`. Ограничения: 301 / 302 / 307 / 308.

Пример: `301`.

### `preserve_uri`

<!-- setting:preserve_uri -->
Добавляет исходный URI с параметрами к адресу назначения. Отключите для перенаправления всегда на один фиксированный URL.

Формат: `boolean`. По умолчанию: `true`.

Пример: `true`.

### `certificate_id`

<!-- setting:certificate_id -->
Сертификат для входящего HTTPS, покрывающий все домены перенаправления. Без него listener остаётся HTTP; сертификат назначения настраивается на другом сервере.

Формат: `string / null`. По умолчанию: `null`.

Пример: `"<resource-id>"`.

## Пример работы

Создайте ресурс с понятным названием, заполните обязательные поля и сохраните. Проверьте завершение apply в «Операциях». При ошибке angie -t исправьте параметры или зависимости; прежняя рабочая конфигурация сохраняется. Observer читает данные, admin удаляет ресурсы, которые больше не используются.
