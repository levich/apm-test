# Сертификаты

Загрузите собственные PEM/ключ или создайте управляемый ACME-сертификат. Для DNS-01 предварительно создайте DNS-профиль. Сертификат подключается к маршрутам по ID. Создание, загрузка и ручной перевыпуск доступны администратору.

## Настройки

### `name`

<!-- setting:name -->
Название ресурса для поиска и выбора в панели, например test. Не меняет его ID и связанные ресурсы.

Формат: `string`. По умолчанию: `обязательно`. Ограничения: minLength=1; maxLength=128.

Пример: `"test"`.

### `enabled`

<!-- setting:enabled -->
Включает объект в генерируемую конфигурацию. Выключенный объект сохраняется в панели. Изменение вступает в силу после сохранения и успешного применения.

Формат: `boolean`. По умолчанию: `true`.

Пример: `true`.

### `domains`

<!-- setting:domains -->
Домены SAN сертификата без протокола/порта, по одному на строке. Wildcard покрывает один уровень поддоменов и требует DNS-01; корневой домен добавляйте отдельно.

Формат: `array`. По умолчанию: `[]`.

Пример: `["app.example.com"]`.

### `mode`

<!-- setting:mode -->
custom — загрузка PEM и ключа вручную; http — ACME HTTP-01 с доступным внешним TCP/80; dns — DNS-01 с DNS-профилем и поддержкой wildcard.

Формат: `string`. По умолчанию: `"custom"`. Ограничения: custom / http / dns.

Пример: `"custom"`.

### `dns_profile_id`

<!-- setting:dns_profile_id -->
Заранее созданный профиль доступа к DNS. Для DNS-01 нужны права изменения TXT-записей в зоне домена. Создайте и проверьте профиль в «DNS-провайдерах»; секреты в форме хоста вводить не требуется.

Формат: `string / null`. По умолчанию: `null`.

Пример: `"<resource-id>"`.

### `email`

<!-- setting:email -->
Email владельца аккаунта. Для сертификата передаётся ACME CA; для пользователя используется при входе. Укажите адрес, которым управляете.

Формат: `string`. По умолчанию: `""`.

Пример: `"admin@example.com"`.

### `terms_agreed`

<!-- setting:terms_agreed -->
Явное согласие с условиями ACME CA. Необходимо для управляемого сертификата и ручного перевыпуска.

Формат: `boolean`. По умолчанию: `false`.

Пример: `false`.

### `server`

<!-- setting:server -->
URL ACME directory выбранного CA. По умолчанию production Let’s Encrypt. Для тестов используйте staging CA; его сертификаты не доверены браузерами.

Формат: `string`. По умолчанию: `"https://acme-v02.api.letsencrypt.org/directory"`.

Пример: `"https://acme-v02.api.letsencrypt.org/directory"`.

### `profile`

<!-- setting:profile -->
Имя ACME-профиля CA, передаваемое как --required-profile. Оставьте пустым, если CA не требует отдельного профиля.

Формат: `string / null`. По умолчанию: `null`.

Пример: `"your-ca-profile"`.

### `key_type`

<!-- setting:key_type -->
Тип ключа сертификата: ecdsa или rsa. При перевыпуске используется выбранный тип; совместимость клиентов учитывайте отдельно.

Формат: `string`. По умолчанию: `"ecdsa"`. Ограничения: ecdsa / rsa.

Пример: `"ecdsa"`.

### `reuse_key`

<!-- setting:reuse_key -->
Просить Certbot сохранять ключ при обновлениях. По умолчанию выключено, что позволяет обновлять ключ вместе с сертификатом.

Формат: `boolean`. По умолчанию: `false`.

Пример: `false`.

### `must_staple`

<!-- setting:must_staple -->
Добавляет расширение TLS Must-Staple при выпуске. Клиенты могут требовать OCSP stapling; включайте только с подходящим CA и рабочим stapling.

Формат: `boolean`. По умолчанию: `false`.

Пример: `false`.

### `status`

<!-- setting:status -->
Системное состояние последней обработки; доступно только для чтения. Отдельная проверка файлов и сроков показывает пригодность установленного сертификата.

Формат: `string`. По умолчанию: `"pending"`. Ограничения: pending / ready / error.

Пример: `"pending"`.

### `fingerprint`

<!-- setting:fingerprint -->
Системный SHA-256 идентификатор версии PEM-файлов. Не редактируется; пути версионные, прежние ревизии сохраняются для отката.

Формат: `string / null`. По умолчанию: `null`.

Пример: `"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"`.

### `expires_at`

<!-- setting:expires_at -->
Системный момент окончания действия сертификата, Unix timestamp в секундах UTC. Таблица отображает локальное время и оставшиеся дни.

Формат: `integer / null`. По умолчанию: `null`.

Пример: `1800000000`.

## Статусы, перевыпуск и замена

Состояние выпуска отделено от проверки установленного сертификата. Таблица показывает начало/окончание действия и оставшиеся дни; предупреждение начинается за 30 дней. Проверяются PEM, соответствие ключа, текущий срок и SAN доменов, включая wildcard одного уровня. Отсутствующие файлы, несовпадения и просрочка имеют отдельные статусы.

«Перевыпустить» доступно администратору для включённых http/dns сертификатов и вызывает POST /api/v1/resources/certificates/{id}/renew. Выпуск принудительный (--force-renewal), даже если прежний сертификат ещё действует; действуют лимиты CA. Пока выпуск ожидает или выполняется, повтор запрещён (HTTP 409). После успеха новая версия устанавливается и ставится apply. Ошибка не удаляет прежние файлы. Для custom загрузите новый сертификат и соответствующий ключ. Плановое обновление выполняется отдельно и использует --keep-until-expiring.

## Пример работы

Создайте ресурс с понятным названием, заполните обязательные поля и сохраните. Проверьте завершение apply в «Операциях». При ошибке angie -t исправьте параметры или зависимости; прежняя рабочая конфигурация сохраняется. Observer читает данные, admin удаляет ресурсы, которые больше не используются.

## Секреты

### `eab_kid`

<!-- credential:eab_kid -->
External Account Binding key ID выбранного ACME CA; нужен вместе с eab_hmac_key. Для обычного Let’s Encrypt оставьте пустым.

Формат: строка. По умолчанию: не задано; секрет не показывается после сохранения.

### `eab_hmac_key`

<!-- credential:eab_hmac_key -->
EAB HMAC key ACME CA. Нужен вместе с eab_kid; передаётся Certbot через временный файл 0600.

Формат: строка. По умолчанию: не задано; секрет не показывается после сохранения.
