# TCP / UDP

TCP/UDP-проксирование без HTTP. Укажите свободный входящий порт и backend либо группу, затем TLS/PROXY при необходимости. Зарезервированные порты панели запрещены. Администраторы и операторы могут изменять потоки.

## Настройки

### `name`

<!-- setting:name -->
Название ресурса для поиска и выбора в панели, например test. Не меняет его ID и связанные ресурсы.

Формат: `string`. По умолчанию: `обязательно`. Ограничения: minLength=1; maxLength=128.

Пример: `"test"`.

### `enabled`

<!-- setting:enabled -->
Включает объект в генерируемую конфигурацию. Выключенный объект сохраняется в панели. Изменение вступает в силу после сохранения и успешного применения.

Формат: `boolean`. По умолчанию: `true`.

Пример: `true`.

### `listen_port`

<!-- setting:listen_port -->
Входящий порт TCP/UDP на Angie. Порты 80, 81, 443, 8181 и 18081 зарезервированы; адрес backend задаётся отдельно.

Формат: `integer`. По умолчанию: `обязательно`. Ограничения: minimum=1; maximum=65535.

Пример: `9000`.

### `protocol`

<!-- setting:protocol -->
tcp передаёт поток байтов, udp — датаграммы. UDP не поддерживает TCP TLS и входящий PROXY protocol в этой системе.

Формат: `string`. По умолчанию: `"tcp"`. Ограничения: tcp / udp.

Пример: `"tcp"`.

### `host`

<!-- setting:host -->
IP-адрес или имя приложения. В Docker используйте имя сервиса, доступное из сети Angie. Для приложения на macOS с Docker Desktop — host.docker.internal. Адрес 127.0.0.1 означает собственное окружение Angie.

Формат: `string`. По умолчанию: `обязательно`.

Пример: `"127.0.0.1"`.

### `port`

<!-- setting:port -->
Порт, на котором слушает приложение. Для Docker-сервиса в общей сети нужен внутренний порт контейнера, например 8080. Внешний порт прокси-хоста эта настройка не меняет.

Формат: `integer`. По умолчанию: `обязательно`. Ограничения: minimum=1; maximum=65535.

Пример: `8080`.

### `upstream_id`

<!-- setting:upstream_id -->
Заранее созданная группа серверов приложения для балансировки и переключения при отказах. Если выбрана группа, она используется вместо адреса и порта backend этого маршрута.

Формат: `string / null`. По умолчанию: `null`.

Пример: `"<resource-id>"`.

### `certificate_id`

<!-- setting:certificate_id -->
Готовый сертификат для входящего TCP TLS. При отсутствии готовых файлов применение отклоняется. UDP не может использовать этот параметр.

Формат: `string / null`. По умолчанию: `null`.

Пример: `"<resource-id>"`.

### `upstream_tls`

<!-- setting:upstream_tls -->
Включает TLS от Angie до TCP-приложения. Это отдельная настройка от входящего сертификата; используйте с upstream_verify и upstream_sni.

Формат: `boolean`. По умолчанию: `false`.

Пример: `false`.

### `upstream_verify`

<!-- setting:upstream_verify -->
Проверяет HTTPS/gRPCS-сертификат backend по системному набору доверенных CA. Обычно оставляйте включённым. Отключение убирает проверку сертификата, но не исправляет неверный сертификат.

Формат: `boolean`. По умолчанию: `true`.

Пример: `true`.

### `upstream_sni`

<!-- setting:upstream_sni -->
TLS-имя для SNI и проверки сертификата приложения. Обычно это доменное имя из сертификата backend. Если поле пустое, используется настроенный адрес backend.

Формат: `string / null`. По умолчанию: `null`.

Пример: `"app.example.com"`.

### `proxy_protocol_in`

<!-- setting:proxy_protocol_in -->
Ожидать заголовок PROXY protocol перед данными TCP. Клиенты без него не смогут подключиться; используйте только за совместимым балансировщиком.

Формат: `boolean`. По умолчанию: `false`.

Пример: `false`.

### `proxy_protocol_out`

<!-- setting:proxy_protocol_out -->
Передавать PROXY protocol приложению, чтобы сообщить исходный адрес клиента. Приложение должно поддерживать этот формат.

Формат: `boolean`. По умолчанию: `false`.

Пример: `false`.

### `timeout_seconds`

<!-- setting:timeout_seconds -->
Тайм-аут stream-прокси в секундах, по умолчанию 600. Применяется к TCP/UDP-соединениям; это не HTTP-тайм-аут.

Формат: `integer`. По умолчанию: `600`. Ограничения: minimum=1; maximum=86400.

Пример: `600`.

### `advanced`

<!-- setting:advanced -->
Директивы Angie внутри блока server этого хоста, доступные администратору. Не вставляйте полный конфиг или повторно сгенерированные блоки. Кандидат проверяется angie -t; при отклонении сохраняется прежняя рабочая конфигурация.

Формат: `string`. По умолчанию: `""`.

Пример: `""`.

## Пример работы

Создайте ресурс с понятным названием, заполните обязательные поля и сохраните. Проверьте завершение apply в «Операциях». При ошибке angie -t исправьте параметры или зависимости; прежняя рабочая конфигурация сохраняется. Observer читает данные, admin удаляет ресурсы, которые больше не используются.
