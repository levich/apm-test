# Ключи ECH

Encrypted ClientHello: создайте профиль, сгенерируйте ключ, опубликуйте ECHConfigList в HTTPS DNS record и подтвердите DNS. Затем выберите профиль в TLS-политике. Требуются совместимые модули/библиотека; администратор.

## Настройки

### `name`

<!-- setting:name -->
Название ресурса для поиска и выбора в панели, например test. Не меняет его ID и связанные ресурсы.

Формат: `string`. По умолчанию: `обязательно`. Ограничения: minLength=1; maxLength=128.

Пример: `"test"`.

### `enabled`

<!-- setting:enabled -->
Включает объект в генерируемую конфигурацию. Выключенный объект сохраняется в панели. Изменение вступает в силу после сохранения и успешного применения.

Формат: `boolean`. По умолчанию: `true`.

Пример: `true`.

### `public_name`

<!-- setting:public_name -->
Внешнее имя ECH, например public.example.com. Требуется поддержка ECH и соответствующая DNS-конфигурация.

Формат: `string`. По умолчанию: `обязательно`.

Пример: `"public.example.com"`.

### `domains`

<!-- setting:domains -->
Доменные имена без протокола, порта и пути, по одному на строке. Например: app.example.com. DNS-записи настраиваются отдельно. Для сертификата на *.example.com нужна проверка DNS-01.

Формат: `array`. По умолчанию: `обязательно`.

Пример: `["app.example.com"]`.

### `dns_profile_id`

<!-- setting:dns_profile_id -->
Заранее созданный профиль доступа к DNS. Для DNS-01 нужны права изменения TXT-записей в зоне домена. Создайте и проверьте профиль в «DNS-провайдерах»; секреты в форме хоста вводить не требуется.

Формат: `string / null`. По умолчанию: `null`.

Пример: `"<resource-id>"`.

### `status`

<!-- setting:status -->
Системное состояние ECH: pending — ключ не создан, awaiting_dns — ожидается публикация DNS, ready — подтверждено и готово к TLS-политике. Доступно только для чтения.

Формат: `string`. По умолчанию: `"pending"`. Ограничения: pending / awaiting_dns / ready.

Пример: `"pending"`.

### `config`

<!-- setting:config -->
Системный ECHConfigList для публикации в HTTPS-записи DNS. Создаётся генерацией ключа; не редактируется вручную.

Формат: `string`. По умолчанию: `""`.

Пример: `"<generated ECHConfigList>"`.

### `current_key`

<!-- setting:current_key -->
Идентификатор активного ECH-ключа. Меняется после успешного подтверждения DNS.

Формат: `string`. По умолчанию: `""`.

Пример: `"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"`.

### `previous_key`

<!-- setting:previous_key -->
Предыдущий ключ ECH для плавной ротации. Хранится вместе с текущим; доступен только для чтения.

Формат: `string`. По умолчанию: `""`.

Пример: `null`.

### `pending_key`

<!-- setting:pending_key -->
Созданный, но ещё не подтверждённый в DNS ключ ECH. Выполните публикацию HTTPS-записи и действие проверки DNS.

Формат: `string`. По умолчанию: `""`.

Пример: `"bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb"`.

## Пример работы

Создайте ресурс с понятным названием, заполните обязательные поля и сохраните. Проверьте завершение apply в «Операциях». При ошибке angie -t исправьте параметры или зависимости; прежняя рабочая конфигурация сохраняется. Observer читает данные, admin удаляет ресурсы, которые больше не используются.
