# Журналы Angie

Раздел «Журналы Angie» показывает запросы (`access.log`) всем авторизованным пользователям. Администратору также доступен журнал ошибок (`error.log`). Новые записи расположены сверху; кнопки «Старее» и «Новее» переключают страницы. Можно выбрать 50, 100, 200 или 500 записей на странице. Кнопка «Обновить» сохраняет применённые фильтры. Автообновление каждые 5 секунд действует на первой странице, пока вкладка видима.

Включите `access_logs` в [настройках сервера](runtime.md); по умолчанию он выключен. Дождитесь успешного применения и отправьте запросы к управляемому хосту. Поля записи: time, host, ip, method, path, status, bytes, duration. Query-параметры в URI не сохраняются. `mask_log_ips` управляет маскированием адресов; поиск видит только сохранённое значение IP.

## Поиск и фильтры

Введите текст и нажмите «Применить фильтры» или Enter. Поиск без учёта регистра ищет буквальное вхождение во всей записи, включая URI и сообщение ошибки. Хост и IP ищутся по части значения; HTTP-метод сравнивается целиком. Все заполненные фильтры действуют одновременно.

- Запросы: хост, IP, HTTP-метод и точный статус (`404`, `502`) либо класс (`4xx`, `5xx`).
- Ошибки: уровень `emerg`, `alert`, `crit`, `error`, `warn`, `notice`, `info` или `debug`. Хост, IP и метод доступны, когда Angie записал соответствующий контекст запроса.
- Период «С» / «По»: местное время браузера, обе границы включены. Записи без распознаваемого времени исключаются при фильтрации по периоду. Время стандартного error log интерпретируется в часовом поясе сервера APM; для существующей установки часовые пояса Angie и APM должны совпадать.

«Сбросить фильтры» очищает условия для выбранного журнала. Применённые условия и страница сохраняются в адресе: ссылку можно открыть повторно. После поступления новых записей или ротации состав страниц может измениться.

Поиск проверяет последние 4 МиБ, максимум 10 000 записей **текущего** файла, затем применяет фильтры и разбивает результаты на страницы. При ограничении окна появляется предупреждение. Ротированные файлы не включаются в просмотр. Повреждённые или неструктурированные строки отображаются текстом и доступны для поиска.

## API

`GET /api/v1/logs/access` и `GET /api/v1/logs/error` принимают `q`, `host`, `ip`, `method`, `status`, `level`, `since`, `until`, `limit` (1–500, по умолчанию 200), `offset` (0–10 000). Даты — ISO 8601; используйте явный часовой пояс, например `2026-10-25T10:00:00%2B03:00`. `status` относится к запросам, `level` — к ошибкам. Ответ содержит `entries`, `exists`, `scanned`, `matched`, `offset`, `limit`, `has_more`, `truncated`. Доступ к error log проверяется сервером и разрешён только администратору.

## Хранение и существующая установка

Управляемый Angie записывает ошибки уровня `warn` и выше в `APM_DATA_DIR/logs/error.log`. Для существующей установки политика логов хоста сохраняется: направьте нужный `error_log` в этот общий каталог вручную, если хотите видеть его в панели. APM access logs относятся к его виртуальным хостам.

Ротация переименовывает файл свыше 20 МБ и просит агента reopen. Очистка использует `APM_METRICS_RETENTION_DAYS`. Административные действия находятся отдельно в [аудите](audit.md), применение конфигурации — в [операциях](operations.md).
