# Прокси-хосты

HTTP(S) и gRPC-маршруты к приложениям. Создайте backend/upstream и политики, задайте домены, затем SSL и пути. Сохранение ставит применение в очередь; результат проверяйте в «Операциях». Доступны администратору и оператору; оператор не меняет административные политики.

## Настройки

### `name`

<!-- setting:name -->
Произвольное название для поиска объекта в панели. У прокси-хоста входящие запросы сопоставляются с полем «Доменные имена», а не с этим названием.

Формат: `string`. По умолчанию: `обязательно`. Ограничения: minLength=1; maxLength=128.

Пример: `"test"`.

### `enabled`

<!-- setting:enabled -->
Включает объект в генерируемую конфигурацию. Выключенный объект сохраняется в панели. Изменение вступает в силу после сохранения и успешного применения.

Формат: `boolean`. По умолчанию: `true`.

Пример: `true`.

### `path`

<!-- setting:path -->
Путь URL, который обрабатывает маршрут, например / или /api/. Основной / принимает запросы, не попавшие в более точный настроенный путь. Для отдельных частей сайта добавьте дополнительные маршруты.

Формат: `string`. По умолчанию: `"/"`.

Пример: `"/"`.

### `host`

<!-- setting:host -->
IP-адрес или имя приложения. В Docker используйте имя сервиса, доступное из сети Angie. Для приложения на macOS с Docker Desktop — host.docker.internal. Адрес 127.0.0.1 означает собственное окружение Angie.

Формат: `string`. По умолчанию: `"127.0.0.1"`.

Пример: `"127.0.0.1"`.

### `port`

<!-- setting:port -->
Порт, на котором слушает приложение. Для Docker-сервиса в общей сети нужен внутренний порт контейнера, например 8080. Внешний порт прокси-хоста эта настройка не меняет.

Формат: `integer`. По умолчанию: `8080`. Ограничения: minimum=1; maximum=65535.

Пример: `8080`.

### `scheme`

<!-- setting:scheme -->
Протокол соединения Angie с приложением: HTTP, HTTPS, gRPC или gRPCS. Выберите тот, который принимает приложение. HTTPS для браузера настраивается отдельно во вкладке SSL.

Формат: `string`. По умолчанию: `"http"`. Ограничения: http / https / grpc / grpcs.

Пример: `"http"`.

### `upstream_id`

<!-- setting:upstream_id -->
Заранее созданная группа серверов приложения для балансировки и переключения при отказах. Если выбрана группа, она используется вместо адреса и порта backend этого маршрута.

Формат: `string / null`. По умолчанию: `null`.

Пример: `"<resource-id>"`.

### `access_ids`

<!-- setting:access_ids -->
Упорядоченные списки IP-правил и Basic Auth. Порядок меняется стрелками. Первый список определяет сочетание проверок и передачу заголовка Authorization. Пустой выбор не добавляет список доступа на этом уровне.

Формат: `array`. По умолчанию: `[]`.

Пример: `[]`.

### `access_mode`

<!-- setting:access_mode -->
inherit использует списки пути или наследует списки хоста, если своих нет. replace требует собственный список пути. public убирает IP/Basic Auth для пути; внешняя авторизация и другие защиты хоста продолжают действовать.

Формат: `string`. По умолчанию: `"inherit"`. Ограничения: inherit / replace / public.

Пример: `"inherit"`.

### `auth_provider_id`

<!-- setting:auth_provider_id -->
Передаёт проверку доступа настроенному сервису авторизации, например Authelia или Authentik. Путь без собственного провайдера наследует провайдер хоста. Сервис авторизации должен быть доступен Angie.

Формат: `string / null`. По умолчанию: `null`.

Пример: `"<resource-id>"`.

### `strip_prefix`

<!-- setting:strip_prefix -->
Для HTTP/HTTPS-backend заменяет совпавший префикс пути на /. Для маршрута /api/ запрос /api/users уйдёт как /users. Оставьте выключенным, если приложение ожидает /api/users.

Формат: `boolean`. По умолчанию: `false`.

Пример: `false`.

### `domains`

<!-- setting:domains -->
Доменные имена без протокола, порта и пути, по одному на строке. Например: app.example.com. DNS-записи настраиваются отдельно. Для сертификата на *.example.com нужна проверка DNS-01.

Формат: `array`. По умолчанию: `обязательно`. Ограничения: minItems=1.

Пример: `["app.example.com"]`.

### `tls`

<!-- setting:tls -->
HTTP-01 подтверждает домен через внешний TCP-порт 80; DNS должен указывать на сервер. DNS-01 создаёт TXT-запись через DNS-профиль и подходит для wildcard-имён. Для DNS-01 внешний порт 80 не нужен.

Формат: `string`. По умолчанию: `"off"`. Ограничения: off / http / dns / certificate.

Пример: `"off"`.

### `certificate_id`

<!-- setting:certificate_id -->
Сертификат для входящих TLS-соединений. В форме прокси-хоста выберите готовый или запросите новый. Он должен покрывать все домены. Новый запрос ставится в очередь при сохранении; для HTTPS нужны успешный выпуск и применение.

Формат: `string / null`. По умолчанию: `null`.

Пример: `"<resource-id>"`.

### `dns_profile_id`

<!-- setting:dns_profile_id -->
Заранее созданный профиль доступа к DNS. Для DNS-01 нужны права изменения TXT-записей в зоне домена. Создайте и проверьте профиль в «DNS-провайдерах»; секреты в форме хоста вводить не требуется.

Формат: `string / null`. По умолчанию: `null`.

Пример: `"<resource-id>"`.

### `acme_email`

<!-- setting:acme_email -->
Email для ACME-аккаунта в центре сертификации. Укажите адрес, которым управляете. Это не доменное имя, не логин приложения и не учётные данные DNS API.

Формат: `string`. По умолчанию: `""`.

Пример: `"admin@example.com"`.

### `acme_terms_agreed`

<!-- setting:acme_terms_agreed -->
Явное согласие с условиями выбранного центра сертификации перед запросом сертификата. Флажок обязателен для нового запроса. Открытие справки не принимает условия и не запускает выпуск.

Формат: `boolean`. По умолчанию: `false`.

Пример: `false`.

### `force_ssl`

<!-- setting:force_ssl -->
Перенаправляет HTTP-запросы приложения на HTTPS при включённом TLS. Клиентам должен быть доступен HTTPS-порт. Путь проверки ACME HTTP-01 остаётся доступен для подтверждения домена.

Формат: `boolean`. По умолчанию: `true`.

Пример: `true`.

### `http2`

<!-- setting:http2 -->
Разрешает HTTP/2 на входящем TLS-соединении: несколько запросов браузера могут идти по одному соединению. Протокол между Angie и приложением эта настройка не выбирает.

Формат: `boolean`. По умолчанию: `true`.

Пример: `true`.

### `http3`

<!-- setting:http3 -->
Включает HTTP/3 поверх QUIC на входящем HTTPS-порту. Нужны поддержка в Angie и доступный UDP на HTTPS-порту, обычно 443. Одного проброса TCP недостаточно.

Формат: `boolean`. По умолчанию: `false`.

Пример: `false`.

### `locations`

<!-- setting:locations -->
Дополнительные пути URL со своим адресом приложения и настройками доступа. Например, /api/ можно направить на API-сервис, а остальной сайт — на основной backend. Одинаковые пути добавлять нельзя.

Формат: `array`. По умолчанию: `[]`.

Пример: `[{"path": "/api", "host": "127.0.0.1", "port": 8081}]`.

### `locations.path`

Путь URL, который обрабатывает маршрут, например / или /api/. Основной / принимает запросы, не попавшие в более точный настроенный путь. Для отдельных частей сайта добавьте дополнительные маршруты.

<!-- setting:request_buffering -->

Пример: `false`.

<!-- setting:upstream_verify -->

Это отключает проверку сертификата и имени backend. У прокси-хоста настройка действует для всех HTTPS/gRPCS-маршрутов. По умолчанию проверка включена.

Блок «TLS до backend» появляется при выборе HTTPS или gRPCS для основного или дополнительного маршрута. Снимите «Проверять TLS-сертификат backend», сохраните хост и дождитесь успешного применения в «Операциях».

Пример: `true`.

<!-- setting:upstream_sni -->

Формат: `string / null`. По умолчанию: `null`.

Пример: `"off"`.

Пример: `0`.

<!-- setting:connection_limit -->

<!-- setting:timeout_seconds -->

<!-- setting:blocked_user_agents -->

### `websocket`

<!-- setting:websocket -->
Передаёт заголовки Upgrade и Connection для WebSocket. Обычно оставляйте включённым для чатов, панелей с обновлениями в реальном времени и других WebSocket-приложений.

Формат: `string`. По умолчанию: `""`.

## Доступность и SSL

Проверки выполняет агент из сети Angie каждые 30 секунд, до 8 соединений одновременно, с тайм-аутом 3 секунды. Данные старше 90 секунд считаются устаревшими. HTTP GET идёт к настроенному пути; strip_prefix заменяет его на /. Используются Host первого домена, upstream_sni и upstream_verify. Ответ 2xx–4xx означает доступность, 5xx — ошибку, редирект не обходится. gRPC проверяется подключением TCP, gRPCS — TLS. Это проверка соединения, не gRPC Health API. Проверяются все пути и все не down узлы, включая backup: смешанный результат означает «Частично доступен». Изменение адресов сбрасывает прежние данные.

Имя открывает первый обычный домен; wildcard требует конкретного поддомена. SSL показывает настройку хоста, а корректность — сохранённые PEM/ключ, сроки и SAN. Проверка не подключается к внешнему домену и не подтверждает публичное доверие CA. Сохранение и выпуск ещё не означают завершённое применение; проверьте «Операции».

## Пример работы

Создайте ресурс с понятным названием, заполните обязательные поля и сохраните. Проверьте завершение apply в «Операциях». При ошибке angie -t исправьте параметры или зависимости; прежняя рабочая конфигурация сохраняется. Observer читает данные, admin удаляет ресурсы, которые больше не используются.
