# Списки доступа

Упорядоченные IP-правила и Basic Auth. Создайте список, затем выберите его на хосте или пути. Первый совпавший IP-rule решает доступ; порядок связанных списков сохраняется. Администратор и оператор могут изменять списки. Удаление связанных ресурсов запрещено.

## Настройки

### `name`

<!-- setting:name -->
Название ресурса для поиска и выбора в панели, например test. Не меняет его ID и связанные ресурсы.

Формат: `string`. По умолчанию: `обязательно`. Ограничения: minLength=1; maxLength=128.

Пример: `"test"`.

### `enabled`

<!-- setting:enabled -->
Включает объект в генерируемую конфигурацию. Выключенный объект сохраняется в панели. Изменение вступает в силу после сохранения и успешного применения.

Формат: `boolean`. По умолчанию: `true`.

Пример: `true`.

### `rules`

<!-- setting:rules -->
IP-правила проверяются сверху вниз до первого совпадения. Допустимы IPv4, IPv6, CIDR (10.0.0.0/8) и all. Если правила есть, но нет записи all, APM добавляет deny all. Пустой список не ограничивает IP.

Формат: `array`. По умолчанию: `[]`.

Пример: `[{"action": "allow", "address": "10.0.0.0/8"}]`.

### `rules.action`

<!-- setting:rules.action -->
allow разрешает совпавший адрес, deny запрещает. Решение задаёт первое совпавшее правило. Узкие исключения размещайте выше широких сетей и all.

Формат: `string`. По умолчанию: `обязательно`. Ограничения: allow / deny.

Пример: `"allow"`.

### `rules.address`

<!-- setting:rules.address -->
IP, сеть CIDR, например 192.168.1.0/24 или 2001:db8::/32, либо all для всех адресов. Доменные имена не поддерживаются. IP клиента зависит от настройки доверенных прокси.

Формат: `string`. По умолчанию: `обязательно`.

Пример: `"10.0.0.0/8"`.

### `users`

<!-- setting:users -->
Имена пользователей Basic Auth. Для новых имён задайте пароли в «Учётных данных». Сохранённые пароли не показываются; добавление одного имени не создаёт пароль. Пустые пользователи и правила не ограничивают доступ.

Формат: `array`. По умолчанию: `[]`.

Пример: `["alice"]`.

### `satisfy`

<!-- setting:satisfy -->
all требует прохождения и IP-проверки, и Basic Auth; any разрешает доступ при успешной любой из проверок. Участвуют только настроенные проверки. При нескольких списках satisfy берётся из первого.

Формат: `string`. По умолчанию: `"all"`. Ограничения: all / any.

Пример: `"all"`.

### `pass_auth`

<!-- setting:pass_auth -->
Передавать заголовок Authorization клиента приложению. По умолчанию выключено: APM очищает заголовок. Включайте, если приложению нужны эти данные. При нескольких списках значение берётся из первого.

Формат: `boolean`. По умолчанию: `false`.

Пример: `false`.

## Пример и пароли

Для внутренней сети задайте allow 10.0.0.0/8; затем deny all. Для исключения поставьте более конкретное правило выше. В поле учётных данных вводите по одному username=password на строке. Пустое поле при редактировании сохраняет прежние пароли; заполненное заменяет весь набор. Чтобы убрать Basic Auth, очистите users. Сохранённые пароли не показываются и не восстанавливаются из интерфейса.

При нескольких списках satisfy и pass_auth берутся из первого. Путь inherit наследует списки хоста, replace требует собственный список, public явно убирает IP/Basic Auth; внешний auth_request продолжает действовать.

## Пример работы

Создайте ресурс с понятным названием, заполните обязательные поля и сохраните. Проверьте завершение apply в «Операциях». При ошибке angie -t исправьте параметры или зависимости; прежняя рабочая конфигурация сохраняется. Observer читает данные, admin удаляет ресурсы, которые больше не используются.

## Секреты

### `credentials`

<!-- credential:credentials -->
По одному username=password на строке. Пустое поле сохраняет пароли, заполненное заменяет весь набор. Секреты доступны только для записи.

Формат: строка. По умолчанию: не задано; секрет не показывается после сохранения.
