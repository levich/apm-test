# Операции

Сохранение ресурса фиксирует желаемое состояние и ставит задание в очередь. Worker обрабатывает очередь последовательно; выпуск сертификата и применение — отдельные задания. pending означает ожидание, running — выполнение, succeeded — завершение, failed — ошибку. Страница обновляется каждые 5 секунд, пока не открыта форма. Доступна всем пользователям.

Применение включает генерацию именованных фрагментов, angie -t, переключение current, reload и подтверждение generation. Ошибка кандидата сохраняет прежнюю версию. Если откат не удался, новые apply блокируются: исправьте Angie и журнал применения локально, затем выполните apm resume-applies. Другие необходимые операции, например очистка DNS, продолжаются.

Операция содержит название объекта, результат, причину и следующий шаг. В «Технических сведениях» доступны ID, тип и безопасная диагностика; секретные snapshot и токены не показываются. Контекст новых заданий сохраняется после переименования/удаления ресурса. Исторические задания без контекста имеют общее название. Ошибку backend мониторинга исправляйте отдельно: она не откатывает административную конфигурацию.

Безопасное применение включено по умолчанию. После reload ручное изменение получает статус awaiting_confirmation. На любой странице панели появляются результаты проверок, таймер и кнопки «Подтвердить доступ» / «Откатить сейчас». Подтверждает администратор либо та же сессия оператора, которая создала изменение. В managed-режиме подтверждение доступно только через новую конфигурацию Angie; прямой backend панели для подтверждения не подходит. Обновление страницы и фоновые запросы не подтверждают изменение.

Срок, отмена, перезапуск агента или три последовательных провала обязательных проверок возвращают прежнюю ревизию. Agent и отдельный watchdog работают независимо от manager/worker. Вторая конфигурация не применяется до решения по первой; другие задания, включая очистку DNS, продолжаются. После отката apply приостановлены до локального восстановления. Желаемые ресурсы остаются черновиком: пользователи, аудит и база целиком не откатываются.

Перед изменением выполняется исходный замер. Для ручного применения уже неработавшие дополнительные проверки показываются в baseline и не считаются регрессией. Проверка панели остаётся обязательной. Автоматическое применение (discovery, сертификаты и другие внутренние задания) допускается только при успешном исходном замере всех проверок и успешной проверке после переключения.

Предупреждения angie -t с кодом завершения 0 не блокируют применение и показываются в операции и JSON API. Известные предупреждения имеют безопасное описание и, если возможно, файл/строку ревизии. Произвольный stderr не сохраняется: он может содержать секреты. Неизвестные предупреждения требуют просмотра локального error.log или ручного angie -t. Ненулевой код завершения отклоняет конфигурацию до переключения.

В existing-режиме проба защищает include APM; основной конфиг владельца остаётся вне отката. Проверка панели использует APM_PUBLIC_URL/health/live с обычной проверкой TLS. Локальные проверки не заменяют внешнюю проверку DNS, firewall и доступности с клиентского устройства.
