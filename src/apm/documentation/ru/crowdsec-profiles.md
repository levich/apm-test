# CrowdSec / AppSec

Защита CrowdSec/AppSec. Подготовьте Lua-модули и сервисы, внесите адреса и ключи, подключите один общий профиль к нужным хостам. Для AppSec включите request_buffering. Управляет администратор.

## Настройки

### `name`

<!-- setting:name -->
Название ресурса для поиска и выбора в панели, например test. Не меняет его ID и связанные ресурсы.

Формат: `string`. По умолчанию: `обязательно`. Ограничения: minLength=1; maxLength=128.

Пример: `"test"`.

### `enabled`

<!-- setting:enabled -->
Включает объект в генерируемую конфигурацию. Выключенный объект сохраняется в панели. Изменение вступает в силу после сохранения и успешного применения.

Формат: `boolean`. По умолчанию: `true`.

Пример: `true`.

### `lapi_url`

<!-- setting:lapi_url -->
Origin API CrowdSec LAPI, доступный Angie. Для доступа задайте api_key в секретах профиля; требуется Lua-интеграция.

Формат: `string`. По умолчанию: `"http://127.0.0.1:8080"`.

Пример: `"http://127.0.0.1:8080"`.

### `appsec_url`

<!-- setting:appsec_url -->
Origin CrowdSec AppSec, доступный Angie. Используется при включённом appsec; проверяйте адрес и порт отдельно от LAPI.

Формат: `string`. По умолчанию: `"http://127.0.0.1:7422"`.

Пример: `"http://127.0.0.1:7422"`.

### `appsec`

<!-- setting:appsec -->
Включить проверку запросов AppSec. На связанных хостах требуется request_buffering=true; один общий CrowdSec-профиль на сервер.

Формат: `boolean`. По умолчанию: `true`.

Пример: `true`.

### `observe`

<!-- setting:observe -->
Наблюдать решения CrowdSec без блокировки. Используйте для проверки интеграции перед включением применения решений.

Формат: `boolean`. По умолчанию: `false`.

Пример: `false`.

### `failure_action`

<!-- setting:failure_action -->
При недоступности сервиса защиты deny запрещает запрос, allow пропускает. Выберите требуемое поведение при отказе.

Формат: `string`. По умолчанию: `"deny"`. Ограничения: deny / allow.

Пример: `"deny"`.

### `captcha_provider`

<!-- setting:captcha_provider -->
Провайдер CAPTCHA: off, recaptcha, hcaptcha или turnstile. Для включённого провайдера нужны site_key и secret_key.

Формат: `string`. По умолчанию: `"off"`. Ограничения: off / recaptcha / hcaptcha / turnstile.

Пример: `"off"`.

## Пример работы

Создайте ресурс с понятным названием, заполните обязательные поля и сохраните. Проверьте завершение apply в «Операциях». При ошибке angie -t исправьте параметры или зависимости; прежняя рабочая конфигурация сохраняется. Observer читает данные, admin удаляет ресурсы, которые больше не используются.

## Секреты

### `api_key`

<!-- credential:api_key -->
CrowdSec bouncer API key для LAPI. Создайте ключ у сервиса CrowdSec и внесите только в секрет профиля.

Формат: строка. По умолчанию: не задано; секрет не показывается после сохранения.

### `site_key`

<!-- credential:site_key -->
Публичный ключ выбранного CAPTCHA-провайдера; требуется вместе с secret_key при включённой CAPTCHA.

Формат: строка. По умолчанию: не задано; секрет не показывается после сохранения.

### `secret_key`

<!-- credential:secret_key -->
Секрет CAPTCHA-провайдера, соответствующий site_key. Доступен только на запись.

Формат: строка. По умолчанию: не задано; секрет не показывается после сохранения.
